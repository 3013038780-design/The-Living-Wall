# 碎光硬件互动：中间进度快照

日期：2026-09-19。Refs #25。分支：`3013038780-design/25-depth-regions`。

**状态：WIP，仅团队同步。真实墙面互动未验收；不合并main、不部署线上。**

## 目标与当前阻塞

目标是让墙前半米内的手驱动原版碎光的呼吸、抚摸与陪伴反应，不要求触墙。不是以完成测试后台或报告功能作为完成标准。

实机曾识别出完整手部，取得有效离墙估计并输出 active=true，但用户在投影校准点处仍不能稳定记录、互动。问题尚未完整定位。投影范围与相机视野不能默认相同；固定四角校准缺少实际覆盖验证，二维映射也未补偿手前后移动造成的视差。

最新一次直接查看相机画面：墙上的1号标记在相机图像约(27%,44%)处，位于当前ROI内。因此不能断言“1号点完全在镜头外”；其他点尚未验证，看到标记也不代表手在该处可稳定识别。此前发现镜像显示，现已确认切为扩展显示。以上是单次现场观察，不是精度认证。

## 已有代码

- Gemini 335真实彩色/深度采集、SDK深度对齐彩色、空墙参考与局部距离采样。
- 浏览器单手节点检测，手腕及四个指根平均估算中心，不是掌背朝向分类。
- 半米内150ms激活，超过530mm退出；无可靠深度不激活互动。
- `detected`与`active`分离：校准可只使用新鲜的手部位置，正式互动仍要求距离有效。输入500ms过期，原生命端300ms无更新停止输入。
- 8773机器视觉后台：同快照彩色/深度预览、节点和中心、逐级诊断。
- 8773投影页：嵌入3018的原版Creature/CreatureRenderer，经消息接口接入原版输入；已移除临时粒子替身。原版成长存储仍留在本机浏览器，不迁移线上存档。
- 实验四点透视映射，窗口尺寸变化即失效。**保留作为排查代码，目前不应要求用户反复做这套流程。**
- 可选五步数值记录，以及投影关闭/开启各8秒的对比记录；逐条写本机，未完成可回看，无彩色视频。投影状态由操作者确认，软件没有控制投影仪。

## 成员如何启动

1. 使用此分支，先阅读根目录AGENTS.md。本机Python虚拟环境、SDK和手部模型不在Git中；新机器按 `tools/depth-lab/README.md` 的依赖说明安装，不要复制本机venv符号链接。
2. 项目根目录 `npm ci`，使用Node 22.13或更新版本。
3. Gemini 335接Mac，投影仪设置扩展显示。固定相机与投影，暂停自动/手动调整尺寸和梯形校正。
4. 执行 `tools/depth-lab/启动手部感应后台.command`，在本机终端输入管理员密码；保持窗口打开。8769是相机服务。
5. 执行 `tools/depth-lab/启动墙面互动.command`；脚本按需启动原网站3018和桥接8773。若第一脚本打开页面时8773尚未启动，等第二脚本完成再打开页面即可。
6. Mac独立窗口显示 `http://127.0.0.1:8773/hands`；投影独立窗口显示 `http://127.0.0.1:8773/projection`。不要只在同一浏览器窗口切标签。保持识别页面可见。
7. 先观察彩色图是否真的拍到手、关节是否持续存在。不要把空墙、单次active=true或模拟按键成功当成完整验收。

## 已知限制 / 不要误判

- 手部识别在浏览器中运行，页面隐藏/节流可能影响更新；还不是独立常驻的后端推理。
- 多个手部页面可以同时向同一桥接写入，尚未实现唯一生产者仲裁。排查时只保留一个8773/hands。
- 曾混用旧8769/hands与新版8773。现在旧入口/file入口自动转向8773，但已经打开的旧页面需要重新导航；旧窗口的绿色线不能证明当前投影已收到数据。
- 当前相机ROI默认中央20%～80%；四点投影目标是15%/85%。两者属于不同坐标系，不能直接比较数值来证明覆盖或不覆盖。
- 现有四点使用手部中心取样，不是固定标记识别。**固定标记自动对应、重叠区计算、三维点到墙面投影，均尚未实现。**
- 仅本地实验；thelivingwall.cn没有因本次改动上线。
