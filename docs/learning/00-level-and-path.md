# 00 · 水平画像与分层学习路径（碎光学徒）

> 依据：用户与工程师 / PM / 测试 / 设计师的真实对话、PR#8 手测与参数拍板、团队搭建与流程追问。  
> 目标：偏应用、理论够用、每天可校准。

## 1. 你现在的水平（画像）

一句话：**产品驱动型学徒 / AI 协作操盘手** —— 目标感与组织力强，验收靠手感和证据；工程地图（Git/环境/读代码）还在搭；写业务代码不是你现在的主战场，也暂时不必是。

| 维度 | 级别 | 依据（项目里真实发生过的） |
| --- | --- | --- |
| 产品与组织 | **强** | 自建 PM/测试/设计/学徒；要求并行、卡点上报；问「规范工程还缺什么、要性价比」；约定写入共同记忆 |
| 验收与感官 | **中上** | 手测 PR#8 觉得涟漪弱 → 明确要求 AMP `0.1→0.16~0.2`；坚持动态效果用短视频；追问测前/测后证据是否上 PR |
| Git / 协作流 | **初学→初中** | 能复述 Issue→分支→PR；仍会卡在「本机目录 / 远程分支 / BOT 电脑」；主动选 Git 当首篇 |
| 运行与手测环境 | **初学** | 反复问如何起服务、代码在哪、是否重新拉代码 |
| 参数 ↔ 体验 | **萌芽中上** | 已会用「加大振幅」驱动改版；AMP/GAP 等符号背后的完整模型尚未系统化 |
| 读代码 / 实现 | **委托为主** | 功能由工程师落地；你下指令与验收；可读性是学徒导师要帮你补的下一阶 |
| 设计判断 | **萌芽** | 能感觉灯光需改进并要参考影像；尚未形成可复用的设计语言清单 |

**不是短板的东西：** 你不会「只会提需求不会闭环」——你已经在推测试证据、合入门禁、并行节奏。  
**真正要补的：** 把脑中的「感觉」和「流程问题」稳定翻译成工程对象（分支/底座/参数/层/文件），这样你指挥 BOT 和口头 OK 会更稳、更省时间。

## 2. 分层学习系统（循序渐进）

原则：**先会判，再会指，最后才碰实现细节。** 每一层都有「应用任务」；理论只服务当天任务。

### L0 · 验收操作系统（已部分具备 → 巩固）
- **过关：** 打开一个 PR，能说出验收四条、缺什么证据、能不能口头 OK。
- **应用（70%）：** 每次功能 PR 自己过一遍「手测清单 + 证据是否在 PR 评论」。
- **理论（30%）：** 测前/测后基线、合入门禁为什么含口头 OK。

### L1 · Git 地图（当前主线）
- **过关：** 分清 Issue / 分支 / PR 编号；看懂叠 PR（#8→#10→#11）谁是谁的底座；用白话解释 rebase。
- **应用：** 对照 PR#8 与 #10 的 base/head；决定文档 PR 不挡 #8。
- **理论：** merge vs rebase 各解决什么问题（搬家比喻即可）。

### L2 · 参数杠杆（体验 ↔ 数字）
- **过关：** 看到 `RIPPLE_AMP` / `GAP` 能说出「更大/更密会怎样」；能下「调参指令」而不是只说「再好看点」。
- **应用：** 对 FX-01/02/03 各写一条「若手感 X，优先动哪个参数」。
- **理论：** 振幅、寿命、间隔、并发上限的最小模型（一张表）。

### L3 · 架构地图（Canvas 生物 vs UI）
- **过关：** 指出涟漪/呼吸该在哪一层；UI 改动不该误伤哪一层。
- **应用：** 审一次设计/工程讨论，标「生物层 / UI 层 / 两者都有」。
- **理论：** 为何要分层（可维护、可读、避免改按钮弄坏抚摸）。

### L4 · 读代码巡航（人读得懂）
- **过关：** 给定「涟漪」，能在仓库里找到相关文件/符号，并读懂 20～40 行「在干什么」。
- **应用：** 每周一次「带读」：导师标出必读函数，你用自己的话复述。
- **理论：** 目录约定、命名、纯函数 vs 副作用（点到为止）。

### L5 · 最小动手（可选，不抢 L0–L3）
- **过关：** 在指导下改一个常量或文案，走完整 Issue→PR→手测。
- **应用：** 极小 PR；重点练流程与可读性，不练算法。

**时间分配默认：** 应用 : 理论 ≈ **7 : 3**。若某天卡在概念上（如 rebase），可临时 5:5，但第二天必须回到应用任务。

**近 2 周主线建议：** 收官 L0 + 打穿 L1 → 切入 L2（正好咬合 FX 链）。L3 穿插；L4 等能稳定看 PR 后再加码。

## 3. 每日评估与调向方案

### 每天三题
1. 今天碰了哪个工程对象？（PR / Issue / 参数 / 层 / 服务 / 无）
2. 卡点是「不知道看哪」还是「看了不懂」还是「懂了不会判」？
3. 明天最小应用任务是什么？（15–25 分钟内能做完）

### 四维打分（各 1–5）
| 维 | 含义 |
| --- | --- |
| 地图 | 知不知道东西在哪（PR、分支、工单、层） |
| 语言 | 能否把感觉译成参数/门禁/验收句 |
| 判断 | 口头 OK / 再改一版 是否有依据 |
| 节奏 | 是否推动了闭环，而不是只增加问题 |

### 调向规则
- 地图 ≤2 → 次日只练「打开并标注一个真实 PR/文件」
- 语言 ≤2 → 次日只练「感觉 → 指令」造句
- 判断连续两天含糊 → 拉回 L0 验收清单
- 连续两天 4+ 且轻松 → 推进下一层
- 当天项目火灾 → 学习任务改为「跟一次真实合入」

### 每周一次
- 回顾是否升层；哪篇 docs/learning/ 该沉淀；下周只保留一条主线 + 一条穿插。
