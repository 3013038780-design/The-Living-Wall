# 00 · 水平画像与分层学习路径（碎光学徒）

> 依据：用户与工程师 / PM / 测试 / 设计师的真实对话、PR#8 手测与参数拍板、团队搭建与流程追问。  
> 目标：偏应用、理论够用、每天可校准。

## 1. 水平画像

一句话：**产品驱动型学徒 / AI 协作操盘手** —— 目标感与组织力强，验收靠手感和证据；工程地图（Git/环境/读代码）还在搭；写业务代码不是主战场。

| 维度 | 级别 |
| --- | --- |
| 产品与组织 | 强 |
| 验收与感官 | 中上 |
| Git / 协作流 | 初学→初中 |
| 运行与手测环境 | 初学 |
| 参数 ↔ 体验 | 萌芽中上 |
| 读代码 / 实现 | 委托为主 |
| 设计判断 | 萌芽 |

真正要补的：把「感觉」和「流程问题」稳定翻译成工程对象（分支/底座/参数/层/文件）。

## 2. 分层（应用:理论 ≈ 7:3）

| 层级 | 内容 | 近况 |
| --- | --- | --- |
| L0 | 验收操作系统（巩固） | 进行中：口头 OK、手测四条、证据挂 PR |
| L1 | Git 地图（当前主线） | 见 `01-git-workflow.md` |
| L2 | 参数杠杆（AMP/GAP 等） | 下一阶段：涟漪手感 ↔ 参数 |
| L3 | Canvas 生物 vs UI | 后续 |
| L4 | 读代码巡航 | 后续 |
| L5 | 最小动手（可选） | 可选 |

**近两周：** 收官 L0 + 打穿 L1 → 切入 L2。

## 3. 每日校准

学徒导师侧可设每日校准（例如 21:00）：四维打分（地图 / 语言 / 判断 / 节奏）+ 调向规则 → 明日最小应用任务。

文档落地仍走工程师 Issue → 分支 → PR，**不挡** 功能 PR（尤其 `#8`）合入。

## 学习建议

- 先把「能不能合 / 依赖谁」说清楚，再学命令细节。  
- 验收用体验语言，参数用表格对照手感。  
- 每天只加一个最小应用任务，避免一次吞下整条 FX 链。
