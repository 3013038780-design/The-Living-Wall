# 碎光本地深度测试台

关联 Issue #25。独立本地工具，不改变线上碎光。面向 Gemini 335 + Apple Silicon Mac，读取 Orbbec SDK 的 Y16 深度及内参，用 SDK 深度比例转毫米，拟合平面法向距离。

## 启动

完成下方虚拟环境安装后，双击 `启动深度测试.command`，或在本目录运行 `.venv/bin/python server.py`，打开 http://127.0.0.1:8765 。终端 Ctrl+C 停止服务；网页“断开”停止采集。

其他 Mac 使用 Python 3.12 ARM64：

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

若 PyPI 无对应 Mac wheel，使用[官方 v2.1.2 发布页](https://github.com/orbbec/pyorbbecsdk/releases/tag/v2.1.2) 的 cp312、macosx_13_0_arm64 wheel。使用虚拟环境，不升级固件或更改系统安全设置。

## 实测步骤

1. USB 3 连接相机，关闭其他占用设备的软件；点击连接。无设备时显示错误，不自动切换模拟。
2. 固定相机，朝向真实空平面，拖动框选；可以用墙或硬板，不要触摸电脑显示器。
3. 移开手，点击校准，采集 30 帧；检查覆盖率、时间稳定度、拟合残差和角度。
4. 伸入单个物体慢慢靠近平面，观察最大前景区域中心和间距。
5. 移动相机或表面必须重新校准。仅内存保存，不跨启动复用。平面大幅变化/遮挡提示未知，但不能检测所有移动，尤其沿平面平移。

## 算法边界

- 最大连通前景区域，不含手部语义、多手 ID 或指尖追踪。
- 间距取区域法向距离的 20% 分位数，不是指尖精确间距。
- 默认 15 mm 是接触候选阈值（可调 8–40 mm），释放迟滞 +5 mm，去抖 150 ms；不是精度承诺。
- 低于噪声下限的区域与平面融合，贴平的手可能消失，边缘/其他物体可能产生候选。因此不能证明物理触碰；后续需 RGB 手部跟踪和真实采样验证。
- 深度缺失/超时显示未知，不沿用接触坐标；失联重新连接并校准。
- 未完成投影映射或接入线上碎光。`/api/state` 的位置是归一化深度画面坐标，不是投影坐标。
- 无保存、上传、录像。只监听 127.0.0.1，限制 Host 和写入 Origin，不提供跨域访问。

## 测试

本目录执行 `.venv/bin/python -m unittest -v test_detector.py`。覆盖倾斜平面、生命周期、迟滞、去抖、噪声、空洞、零星像素、无效校准及重置。模拟模式只验证软件流程，不代表硬件实测。

## 区域诊断版（Refs #25，现场待验收）

本分支权限版启动脚本使用 http://127.0.0.1:8769，与旧版 8767 分开。测试前关闭其他采集相机的进程。
本机依赖已复用；其他机器仍需按开头安装依赖。

新版在深度预览上显示多个几何前景轮廓（蓝）和独立的近墙区域（橙）。
先移开身体、校准空墙，再分别伸入手掌、前臂、上半身；开关“显示区域轮廓”可对照原始深度。
前景带为噪声下限至 800 mm，近墙带上限为 50 mm；两者都不是接触精度承诺。
近墙区域从像素距离独立提取，因此可以显示连接在较远躯干上的近墙手掌。
每类最多显示最大的 12 个区域，每区至少 35 个预览像素；更小的区域会被过滤。
区域编号只在当前帧有效；不含人体语义、左右手分类或稳定身份。轮廓是外边界，内部可能仍有深度空洞。
墙面大面积遮挡时轮廓改虚线，只用于排查，不能作为可靠互动输入。失联清空轮廓。
原有最大区域的“接触候选”指标仅保留作旧算法参考，新区域尚未驱动碎光。
模拟模式提供相连的躯干、前臂与近墙手掌，以及另一个分离区域，用来验证几何流程，不代表硬件实测。

产品影响：只改本地实验工具，线上行为与 PRD 产品能力不变。测试用例不替代真实人体、相机和投影验收。


## 网页动作向导与记录

连接并校准后，点击“开始引导测试”，每一步手动就位后开始：准备5秒，记录10–15秒，然后确认是否实际完成。依次为空墙、手掌悬空、靠近、贴墙、抬手、前臂、上半身、双手、恢复空墙。
仅在浏览器内存中保留时间戳、动作自报、距离/区域数量/覆盖率等数值，不保存图像或轮廓。结束后下载 JSON 发给分析人员；刷新会丢失，页面会提醒。模拟报告明确标记 simulation。未知判断仍作为无效样本保留；断流或模式变化中断当前动作。流程完成不等于验收通过。
JS 状态机验证：`node --test test_guide.mjs`。


## 空墙背景版 v2（Refs #25）

校准30帧时保存逐像素有效深度中位数与时间波动；检测仅接受相对参考墙面向相机方向发生的新变化。距离改为当前点到同一像素参考墙点的法向距离估计，不是指尖接触证明。静止背景不参与前景；背景在校准后冻结，静止手不会被自动吸收。
无可靠参考的像素不检测。阈值为每像素 max(5mm, 4.5×时间绝对偏差中位数)，不稳定参考过多会拒绝校准。改变相机位置或内参/尺寸后必须重新校准；无法检测所有相机移动。低于噪声下限的薄物体仍可能漏检。
报告v2额外记录算法版本、区域面积与归一化中心（无身份、图像、轮廓），用于定位固定误检。旧报告不含这些字段，不能用于证明v2硬件效果。
先校准空墙并保持15秒，再加入/移开手掌；真实现场是否归零仍待验证。

### 自动短测与近墙点跟踪（Issue #25，实验）

真实相机测试台保持在 8769 运行并完成空墙校准后，可独立启动：

```sh
python3 tools/depth-lab/wall_check.py
```

打开 http://127.0.0.1:8771/ ，点击一次「开始测试」。五个动作各有5秒准备时间，总计约71秒；不必逐项点击或手写记录。数值报告逐次原子写入 `~/Documents/LivingWall-test-reports/`，不保存图像。网页关闭不会停止服务端记录，服务退出则保留未完成报告。此页仅供本机操作，不发布到公网。

跟踪输入只取原检测器的近墙区域，持续150ms后显示；相邻位置匹配并平滑，区域消失/数据过期立即清除。远处身体区域不生成交互点。编号不是人物身份；近墙手臂仍可能被当成候选，区域合并/分裂可能换号，不支持语义手掌识别，也不能宣称接触精度。自动报告仅统计动作提示时段，不能证明用户实际执行了动作；人工分析后再决定投影接入。

自动短测页现显示实时深度伪彩画面、白色检测范围和后台具体错误。画面只在本机转发，不进入数值报告。「记住现在的空墙」会重新校准，点击前必须清空白框。连续无效0.8秒会中止测试并保存原因，不再继续倒计时制造完成假象。
